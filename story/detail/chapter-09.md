### ch09-s1「後端照介面寫」

學長・自己｜場景 1｜搭檔：亭瑄｜類別

| 步驟 | 目標 | 驗證 |
|---|---|---|
| 1 判斷的約定 | 寫 `interface Checker { boolean check(String typed); }`，以及兩種實作：`ExactChecker`（去掉前後空白後完全一樣才對）、`OptionChecker`（選項代號一樣就對）。 | 數值 `new ExactChecker("選午餐").check(" 選午餐")`、`new OptionChecker("B").check("B")`、`new OptionChecker("B").check("A")` |
| 2 畫面怎麼改都不會壞 | 寫 `static String judge(Checker c, String typed)`：對就交回 `答對了`，錯就交回 `再試一次`。傳哪一種 Checker 進來都能用。 | 數值 `judge(new ExactChecker("選午餐"), "選午餐")`、`judge(new OptionChecker("B"), "A")` |

- 延續第四章「方法簽章就是分工約定」：介面是更大的約定。
- 解鎖筆記：`interface`、`implements`、`polymorphism`

## 筆記條目

| id | 標題 | 一句話 |
|---|---|---|
| `interface` | 介面是約定 | `interface Drawable { void draw(); }` 只說要會畫，不管怎麼畫。 |
| `implements` | 照約定實作 | `class Button implements Drawable`：約定裡的方法每一個都要寫出來，而且要加 `public`。 |
| `polymorphism` | 多型 | `Drawable[]` 裡可以放按鈕、進度條、小老師。同一句 `draw()`，各自畫各自的。 |
| `abstract` | 抽象類別 | 共用的寫在 `abstract class` 裡，只留 `abstract` 方法給子類別。抽象類別不能直接 `new`。 |

兩個視角各自都會解鎖全部 4 條。學妹在 k1、k2、k4 解鎖；學長在 s1、s2 解鎖。
