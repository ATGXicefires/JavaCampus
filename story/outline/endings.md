# 結局設計

## 四種結局總覽

| 結局 | 內部代號 | 條件 | 調性 |
|------|----------|------|------|
| True End | `1+1>2` | AP≥80, TP≥80, 關鍵抉擇≥2/3 | 完美告白，相擁，開學日陪她走到校門口 |
| Good End | `Merge Request Approved` | AP≥60, TP≥60 | 含蓄確認，老街散步，桌下牽手 |
| Normal End | `Pull Request Pending` | AP≥40 或 TP≥40 | 未說出口的告別，信的留白，未完待續 |
| Comedy Bad End | `Stack Overflow` | AP<40, TP<40 | 轉科，搞笑 txt，帶笑的遺憾 |

## 結局詳細描述

（告白的那一夜見 chapter-11.md「最後的電腦教室夜晚」，結局的完整場景見 chapter-12.md）

時間點：告白在畢業前夕（第十一章），結局在畢業典禮之後（第十二章）。

## 結局的設計哲學

### True End — 用「程式碼」告白
二弘在專題裡偷偷寫了 Easter egg——需要特定輸入才會觸發的隱藏訊息。這完美符合他的角色：不會當面說，但能在程式裡寫出最真誠的話。亭瑄的回應「最爛的情書但也是最好的」，同時吐槽和接受，完美呈現兩人的互動模式。

首尾呼應：第一章的「術語文件」在最後一幕被翻出來，上面有二弘開學時寫的備註，讓整個故事形成閉環。

### Good End — 用「延續」代替告白
沒有正式的告白場景。而是用「繼續一起學程式」代替——這是兩人最自然的連結方式。含蓄但確定，符合兩人在這條路線上的成長軌跡（有好感、有信任，但還不夠勇敢到當面說出口）。

桌下偷偷勾在一起的手、各自螢幕上的小線索（資料夾名、變數名），讓觀眾會心一笑。

### Normal End — 用「留白」創造餘韻
信的內容刻意不展示。二弘的表情變化（困惑→微笑）是唯一的線索。這個結局是為了：
1. 讓玩家自己想像信裡寫了什麼
2. 為大學 DLC 留下最大的敘事空間
3. 表達「有些感情需要更多時間」的主題

### Comedy Bad End — 用「幽默」包裝遺憾
亭瑄的 txt 檔語氣是嘴硬但不絕望。「木瓜牛奶我還是會幫你買的，不過要自己來拿」暗示她並沒有真的放棄。旁白的「下一個 sprint 也許還有機會修」保留了希望。

這個結局不是懲罰——而是「如果你們都不夠努力，故事就只能到這裡。但門沒有關上。」

## 結局與大學 DLC 的銜接

二弘畢業上大學、亭瑄升上二年級之後的篇章，接著教本篇沒教到的 Java（路線圖見 `design/curriculum.md`）。

| 結局 | DLC 可能性 |
|------|-----------|
| True End | 交往日常 + 新的挑戰（不同學校、亭瑄的分科和升學） |
| Good End | 從曖昧到正式確認的過程 |
| Normal End | 重新相遇、信的內容揭曉、第二次機會 |
| Comedy Bad End | 跨科交流、重新連結 |
